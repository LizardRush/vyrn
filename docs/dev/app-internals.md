# Qt app (`vyrn`): structure and behaviour

Binding inputs: `docs/dev/PLAN.md` §4 (the app), `docs/dev/core-internals.md` §4–5 (Session API + events),
`docs/dev/protocol.md` (errors, spec), `docs/dev/package.md` (sharing and trust). The app is **Qt 6.8 Widgets +
QScintilla, C++20**, linking `vyrn_package`, `vyrn_project` and `vyrn_core` through their std-only public headers.
**Never include torch headers in `app/`** (a ctest enforces it).

QScintilla's headers use lowercase `signals:`/`slots:`. Compile the app with `QT_NO_KEYWORDS` and include QScintilla
only through `app/Qsci.h`:
```cpp
#define signals Q_SIGNALS
#define slots Q_SLOTS
#include <Qsci/qsciscintilla.h>
#include <Qsci/qscilexerpython.h>
#include <Qsci/qsciapis.h>
#undef signals
#undef slots
```

## 2. Startup (`main.cpp`)

1. `vyrn::platform::ensure_passive_openmp(argv)`: if `OMP_WAIT_POLICY` is unset, Linux and macOS set it to `PASSIVE`
   and `execv` self (libgomp reads it at load time); Windows sets it for child processes only.
2. `QApplication`; `setApplicationName("Vyrn")`, `setOrganizationName("Vyrn")`,
   **`setDesktopFileName("vyrn")`** (= the Wayland app_id; the focus guard relies on it), window icon.
3. Theme: Fusion style, dark palette, stylesheet; accent `#2dd4bf` (teal).
4. macOS and Windows: the global panic hotkey (§10; not for `--smoke-test`, `--help`, `--version`). When the system
   refuses it, `qApp` gets the property `vyrnPanicKeyProblem` (a sentence) and the red banner and the keys countdown
   stop promising the shortcut.
5. Arguments: `vyrn [project_dir]` opens that project directly; `vyrn <file.vrlp|file.vrl>` (a double-click in the
   file manager, docs/dev/package.md §9) shows the launcher and starts its Open shared file flow (§3);
   `vyrn --smoke-test …` (§9).
6. Otherwise show `LauncherWindow`. Closing the last window quits; a running session is stopped and saved first.
   Before the process ends, a package file still being written on a background thread gets up to 10 s.

## 3. Launcher

- Header "Vyrn — teach an AI with three small Python files", buttons **New project**, **Open folder…**,
  **Setup** (shows "Setup n/m" when checks fail, only for real-game needs once such a project exists).
- Project cards from `~/Vyrn/*/vyrn.json`, newest first: name, mode badge ("Simulation" if `world.py` exists, else
  "Real game"), time trained, best score (from the active brain's meta if the core exposes it, else hidden),
  "Open" on click; context menu Rename / Duplicate / Delete (move to trash with `QFile::moveToTrash`) / Show folder.
- Empty state: a friendly panel "Start with **Catch (pictures)** — your first AI learns in a few minutes".
- Card menu also has **Share project (.vrlp)…** (the ShareDialog of §7; the picture of "what the AI sees" comes
  from the project's window when it is open). Cards of imported projects nobody trusted yet show a
  **Not trusted yet** badge (`ProjectCard::trusted` = `vyrn::is_trusted`).
- **Open shared file…** (link next to "Show projects folder", a button on the empty page, Ctrl+Shift+O), a `.vrl`/
  `.vrlp` dropped anywhere on the launcher, or `vyrn <file>`:
  - `.vrlp` → OpenPackageDialog (Project) → **Import** (`vyrn::import_project` into the projects folder) → the new
    project's window opens (with the trust banner); the import's notes go to its console and a message box.
  - `.vrl` → OpenPackageDialog (BrainChooseProject): pick one of the projects (same template first) or
    "New <template> project with this brain" when the brain names a template Vyrn ships (`list_templates`). The
    chosen (or newly created) project's window opens and adds it with `ProjectWindow::importBrain(file, false)`.

New project dialog: name (sanitized to a folder name), template list from `<data>/templates/*/vyrn.json` with a
one-line description each (Demo game, My game, Catch (pictures), Catch (numbers)); Create copies the template into
`~/Vyrn/<name>/` (never into the data dir), sets `"name"`, opens it.

## 4. Project window

```
┌ toolbar: [✓ Check] [▶ Train] [👁 Watch] [■ Stop] | [⬚ Pick area] [📷 Snapshot] | Brain ▾ | speed ▸ |  Share ▾ ⚙ ┐
│ ┌ red banner (only while the AI presses keys) ──────────────────────────────────────────────────────┐ │
│ ┌ trust banner (imported, not trusted yet) [Trust this project] / lock bar [Stop] / run bar / toast ┐ │
│ ┌ editor tabs ─────────────────────────────────────┐ ┌ right dock ───────────────────────────────┐ │
│ │ inputs.py — what the AI sees | responses.py — …  │ │ What the AI sees (SeesView)                │ │
│ │                                                   │ │ Choices (ChoiceBars)                        │ │
│ │                                                   │ │ Your values (vyrn.show)                     │ │
│ └───────────────────────────────────────────────────┘ └────────────────────────────────────────────┘ │
│ ┌ bottom dock tabs: Console | Points | Problems | Docs ───────────────────────────────────────────────┐ │
└ status: Round 312 · Best 14.2 · Exploring 35% · 10 decisions/s ──────────────────────────────────────┘
```

- Tabs: `inputs.py — what the AI sees`, `responses.py — what its choices do`, `points.py — how it scores`,
  `world.py — the simulated game` (only if present). Other `.py` files are reachable via a "+" menu.
  Unsaved tabs show `•`. External edits reload automatically when the tab has no unsaved changes.
- **Check**: save all → `Session{action: Check}` → results: Problems list + editor marks + a summary toast
  ("Looks good: 3 choices, the AI sees a 10×10 picture").
- **Train**: save all → automatic Check (errors stop; warnings don't) → start Train. For real-time projects whose
  spec uses keys: countdown overlay + `allow_input` (M4). While training: Train is disabled, Stop enabled.
- **Watch**: uses the Brain dropdown's choice (Best by default); sims show the speed slider (0.5×–Max).
- **Stop**: graceful (the session saves); the button shows "Stopping…" until `finished()`.
- **Start program** (vyrn.json `start_program`, Settings → Start program; `StartProgram`, one per window): when the
  person presses Check, Train or Watch (and Start over) on a trusted project with a non-empty `start_program`, the
  window starts it unless the copy it started earlier is still running (the same command; a copy of an older
  command is ended first). `QProcess::splitCommand`, no shell, working directory = the project folder, stdin
  `/dev/null`, output forwarded to Vyrn's own (`ForwardedChannels`), its own process group (`setpgid` in
  `setChildProcessModifier`, so a launcher script and the game it runs end together). Console: "Started
  python3 demo_game.py. Vyrn closes it again when you press Stop or close this window."; then a fixed 2 s wait
  (status "Starting the game…"; Check/Train/Watch disabled, Stop enabled and cancels the wait) before the Check
  (or the sim Watch) begins, so the game is open before the Check and the keys countdown. A program that can't
  start: a plain console line + toast ("Vyrn couldn't start “…”: there's no program called “…” on this computer.
  Check Settings → Start program.") and the run goes on without the wait. **Stop** (the button, the red keys
  banner) and closing the window end it, only if Vyrn started it and it still runs:
  `vyrn::platform::stop_process_tree` (Linux, macOS: SIGTERM to its own process group, set up by
  `app_platform::useOwnProcessGroup`; Windows: `QProcess::terminate`, which closes its windows), then forced after
  3 s (SIGKILL to the group; Windows: the whole process tree) (closing: `~StartProgram` waits for it). A Check that ends by itself, the speed slider's
  Watch restart and the panic key leave it running; a copy the person started themselves is never touched (Vyrn
  only knows its own `QProcess`). When it ends by itself, the console says so ("… has closed.", or the exit code
  with "Try the same command in a terminal…"). Never for an untrusted project (the trust dialog comes first;
  imports never set `start_program`), and **only the app**: vyrn-cli and the MCP server never start it, so AI
  agents can't launch programs this way (comments in `StartProgram.h` and core `util/settings.h`).
- **Saving during a run**: an info bar "You changed a script — Apply changes (keeps the brain)" → `apply_changes()`.
- **Brain ▾**: Best / Latest of the active brain, older brains (time trained, best score) if the core lists them,
  "Start over (new brain)" (confirmation dialog: the old brain is kept and can be picked later), then a Share
  section: **Export this brain (.vrl)…** (ShareDialog, Brain) and **Import a brain (.vrl)…** (file dialog →
  OpenPackageDialog, BrainIntoProject → `importBrain`).
- **Share ▾** (right of the toolbar): **Share project (.vrlp)…** (saves the editors first), **Export this brain
  (.vrl)…**, **How sharing works** (the guide `docs/user/06-sharing.md` in the Docs tab; every `docs/user/*.md` is
  listed there as "Guide: <its # title>").
- **Adding a brain** (`ProjectWindow::importBrain`): refused while this project runs or someone else trains it. A
  trusted project first runs a Check through the window's SessionBridge; when it passes, the `spec` event (as JSON
  text) goes to `vyrn::import_brain(file, project, spec_json)` on a background thread. An untrusted project skips the
  Check (its code may not run): the core compares the brain with the active one. `PackageError` text appears as is
  in a warning box; the import's notes in the console and an information box; success in a toast.
- **Dropping** a `.vrl` on the window = Import a brain; a `.vrlp` = the launcher's import flow (the window emits
  `openProjectRequested(dir, notes)`; without a launcher it opens the new project's window itself). Editors refuse
  such drops (`Editor::canInsertFromMimeData`) so they reach the window.
- **Trust** (docs/dev/package.md §7): when `vyrn::is_trusted(project)` is false, a banner above the editor says "This
  project came from Catch.vrlp (by Ann). Its Python code hasn't run on this computer yet. Read the scripts, then trust
  it." with **[Trust this project]** (opens the TrustDialog, §7). Check, Train, Watch and Start over on an untrusted
  project open the TrustDialog instead ("Trust and run" → `vyrn::trust_project`, then the pressed action goes on).
  Trusted means `vyrn::not_trusted_message(dir)` is empty (the test Session::start makes); it is re-read with the lock
  poll (every 2 s), so `vyrn-cli trust` in a terminal hides the banner. The core's error event of kind `not_trusted`
  (fatal) is shown in plain words (console + toast), cancels what would follow the Check, and shows the banner and
  the TrustDialog.
- Tabs never open `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md` or `GEMINI.md` (notes for AI coding agents that
  templates and imports carry); the "+" menu lists only `.py` files.
- **Status bar** (plain words): `Round 312 · Best 14.2 · Exploring 35% · 10 decisions/s`; tooltip has timings.
- Closing the window stops and saves a running session first ("Saving the brain…"), then ends the Start program
  Vyrn started.
- Project lock (`<project>/.vyrn-lock`, docs/dev/mcp.md §4): the app takes it while training/watching; when an AI
  agent or vyrn-cli holds it, an info bar says "An AI agent is training this project" with **Stop** and Train is
  disabled; the chart can follow the agent's run by tailing `runs/<latest>/rounds.csv`. A `"cli"` holder may be
  training or watching ("vyrn-cli is training or watching this project in a terminal"). **Stop** (after a yes/no
  question) writes an empty `<project>/.vyrn-stop` (`vyrn::kStopMarkerFile`, vyrn/session.h): that program's Session
  deletes it and ends the run the way its own Stop does (Train saves the brain). No signal is sent. The button then
  reads "Asked it to stop…".
- **Frames**: the `spec` event's `"frames"` (pictures the brain sees at once) captions "What the AI sees" ("10×10
  colour, last of 4 frames"); older cores without it: parsed from the net text ("small CNN, 12x10x10" = 4 frames).

### Errors in the editor
Worker errors (`error` events) and warnings carry `script`, `line`, `col`, `message`, `hint`:
margin marker (red circle) + squiggle from `col` to end of the token/line + an inline annotation
"NameError: name 'scor' is not defined — Is it spelled the same as where you made it?". Lines are 1-based in
events, 0-based in QScintilla. The Problems tab lists them; clicking one focuses the tab and line. Marks clear when
the user edits that line or on the next Check/Train.

### Console
Read-only, monospace, max 5000 lines (`setMaximumBlockCount`), stdout normal, stderr in a warm colour, app messages
dimmed. Any `name.py:NUMBER` in a line is clickable (jump to that file/line).

## 5. Editor (`Editor`)

QsciScintilla + `QsciLexerPython`, dark colours set on the lexer (style −1 defaults, then per-style), line-number
margin, marker margin, 4-space indents (`setIndentationsUseTabs(false)`, `setTabWidth(4)`, auto-indent, backspace
unindents), brace matching, current-line highlight, monospace font (first available of "DejaVu Sans Mono", "Noto Sans
Mono", "Monospace", 11 pt). Autocompletion: `QsciAPIs` loaded from `:/vyrn.api` + Python keywords, threshold 2, source
All, call tips in context; `prepare()` once (cache with savePrepared/loadPrepared in the app cache dir). F1 on a
`vyrn.<name>` opens the Docs tab at `#<name>`. Ctrl+S save, Ctrl+F find bar (find next/prev, Esc closes).

## 6. Dashboard widgets

- **PlotWidget**: points per round (thin dots/line) + 20-round mean (thick accent line); x = round, y auto-scaled
  with a 5 % margin and "nice" tick labels; at most 2 drawn points per pixel column (min/max decimation) so 100k
  rounds stay fast; hover shows "Round 312: 4 points (mean 3.6)"; repaints at ≤ 4 Hz; `clear()`, `addRound(round,
  points, mean20)`; empty state text "Points per round appear here once training starts".
- **SeesView**: picture → scaled up with nearest-neighbour, aspect kept, 1-px grid when cells ≥ 12 px; numbers →
  one labelled horizontal bar per input (value normalised to −10..10 shown centred). Title "What the AI sees"; a small
  caption "84×84 colour, last of 4 frames" / "3 numbers".
- **ChoiceBars**: one row per choice label + bar for its probability (0–100 %), the current pick highlighted;
  caption "Exploring 35%" when epsilon > 0.
- **Your values**: `show` text values as a two-column list; `show` pictures as small thumbnails.

## 7. Dialogs

- **SettingsDialog** (writes `vyrn.json`, preserving unknown keys): decisions per second (1–60), round length
  (seconds for real time / ticks for sims), start program, Python interpreter (advanced, with "Test" button), and an
  "AI coding agents" section for real-game projects: [ ] "Let agents look at the screen (Check)" → `"agents":{"screen":true}`.
  Real games also get a **Vyrn Link** card: on/off, port, the address, the pairing code with **New code**, lockstep
  and frames per step → `"link":{...}` or `"link": false` (docs/dev/link.md). The project window shows a Vyrn Link
  bar (object name `linkBar`) above the editor for Link projects, fed by the run's `link` events.
- **SetupDialog** rows (✓ / ✗ / –, explanation, copyable fix and/or buttons), per system (`SetupChecker::appliesHere`;
  rows another system needs aren't shown). Every system: Python (`vyrn::platform::default_python()`, `python3` when
  that file is missing) with numpy + Pillow; macOS and Windows also need Python ≥ 3.10 (the check prints the version
  and exits with 3 when it is older). Fixes: Linux `sudo apt install …`, macOS `brew install python numpy pillow`,
  Windows `winget install -e --id Python.Python.3.12` / `"<python>" -m pip install numpy Pillow`. Real games also
  need, on **Linux**: screen capture (`grim` test grab shown as a thumbnail); keyboard access (`/dev/uinput` writable
  + `python3 -c "import evdev"`); focus helper (`vyrn-focus --once` exits 0 with `ready`); panic keys in
  `~/.config/labwc/rc.xml` (fix for keyboard/panic rows: "Run in a terminal: ./install.sh --keyboard"). **macOS**:
  Screen Recording (`CGPreflightScreenCaptureAccess`, buttons "Open Screen Recording settings" →
  `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture` and "Ask for permission" →
  `CGRequestScreenCaptureAccess`) and Accessibility (`AXIsProcessTrusted`, button "Open Accessibility settings" →
  `…?Privacy_Accessibility`); the worker, started by the app, is covered by the app's permissions (from a terminal:
  the terminal's). **Windows**: nothing (no "Real games also need" section). Sims only need the first row.

- **ShareDialog** (Kind Project → `.vrlp`, Kind Brain → `.vrl`; docs/dev/package.md §1): Author (optional, ≤ 100
  characters, remembered in QSettings `share/author`, never filled in from the system user name), Description
  (≤ 2000 characters), "Include the trained AI" Best / Latest / Don't include (Brain: "Which brain" Best / Latest;
  without a brain: Don't include, disabled), a Preview row when there is a "what the AI sees" picture (PNG via
  `vyrn::png_encode`, enlarged to about 256 px, with an "Include this picture" box). Projects also list "What goes
  in" with the size: a trial `export_project` into the cache folder (background thread, re-run when the brain choice
  or the preview box changes, deleted afterwards). **Save…** → QFileDialog at `~/<suggested_file_name()>` → export on
  a background thread → "Saved Catch.vrlp (412 KB). Anyone with Vyrn can double-click it to open your project and
  watch your AI." with **Show in folder** (QDesktopServices on the folder) and **Done**. Errors (PackageError text)
  stay in the dialog. A name typed without the extension gets it, and is then never overwritten silently.
- **OpenPackageDialog** (`vyrn::inspect_package` on a background thread, "Reading Catch.vrlp…" meanwhile): name,
  author, shared date and size, the preview, the mode ("Simulation" / "Real game: this AI presses keys in the window
  you choose"), the trained AI (time trained · rounds · best 20-round average; what it sees and its choices; a mini
  points chart of `history` in a `PlotWidget::setMeanOnly(true)`), and for projects the files, the Start program hint
  (never set automatically) and the note that its Python code runs on this computer once trusted. Modes: Project
  (**Import** → `import_project`, then accept; Esc is ignored while it writes), BrainChooseProject (**Add brain**:
  the chosen project or template), BrainIntoProject (**Add to this project**). A file that can't be read shows the
  PackageError text and no Import.
- **TrustDialog** (window-modal, `open()`): where the project came from (file, author, import time), what trusting
  means, its `.py` scripts (main ones first, with line counts; clicking one opens its tab and closes the dialog), the
  author's Start program hint (`import_origin`) and, for real-time projects (no world.py), "this AI presses keys in
  the window you choose while it plays". Buttons **Trust and run** (or **Trust this project** from the banner) and
  **Cancel** (the default, so Enter never trusts by accident).

## 8. Pick area / Snapshot (`PickTool`)

- Selecting the area. **Wayland** (Linux with a Wayland platform plugin or `$WAYLAND_DISPLAY`): run
  `slurp -f "%x %y %w %h"` (QProcess, async; Esc cancels). **Elsewhere** (macOS, Windows, X11): `AreaOverlay`, a
  frameless `Qt::Popup` over the screen under the mouse showing `QScreen::grabWindow(0)` of it, dimmed outside the
  rectangle being dragged, with the area's numbers next to it; Esc, a right click or a click on another screen
  cancels; a click without dragging is ignored. Window flags: + `WindowStaysOnTopHint`, except on macOS, where a popup
  already sits above the menu bar and the Dock (stays-on-top would put it below them). macOS without Screen
  Recording: no overlay (the picture would hold only the desktop); a message with "Open Screen Recording settings"
  (and `CGRequestScreenCaptureAccess` once). Never minimize Vyrn.
- Coordinates (`picktool::toArea`, pure, in PickTool.h): what `vyrn.screen()` takes on each system
  (docs/dev/platforms.md). Linux and macOS: logical pixels (points on macOS) = the screen's top-left + the dragged
  rectangle. Windows: physical pixels = the screen's top-left (Qt keeps it in device pixels) + the dragged rectangle ×
  `QScreen::devicePixelRatio()`, each edge rounded on its own so neighbouring areas still meet. Unit test:
  `tests/gui/pick_area_test.cpp` (ctest `gui_pick_area`, labels unit + gui, built by app/CMakeLists.txt).
- Pick area: replace the first `vyrn.screen(...)` call in inputs.py with `vyrn.screen(x=…, y=…, width=…, height=…)` as
  one undoable edit; if none exists, insert it at the cursor.
- Snapshot: area → name dialog (default `game_over.png`) → the picture: Wayland `grim -g "x,y wxh" -t png
  <project>/pictures/<name>`; the overlay crops its screenshot (`picktool::shotRect`) and scales it to the area's size
  in the same units (points on macOS, like Pillow's `ImageGrab`; physical pixels on Windows) → save with
  `QImage::setText("vyrn-area", "x,y,w,h")` → insert `vyrn.on_screen("<name>", x=…, y=…)` at the cursor.

## 9. Smoke test

```
vyrn --smoke-test <project> [--check] [--train-seconds N [--panic]] [--inject-error] [--screenshot out.png]
vyrn --smoke-test --open-package <file.vrlp> [--trust] [--check] [--train-seconds N] [--inject-error] [--screenshot out.png]
       ... [--export-brain out.vrl] [--import-brain file.vrl]     (either form)
```

Copies the project to a temp dir (or, with `--open-package`, imports the package through the OpenPackageDialog,
pressing Import in code, into `$VYRN_PROJECTS` when set, else a temp dir: never `~/Vyrn`), opens it in a
ProjectWindow (normal or `QT_QPA_PLATFORM=offscreen`), runs Check (and Train for N seconds), optionally appends a
NameError line to points.py and runs Check again, then grabs the window (`QWidget::grab()`) to the PNG and prints
one JSON line. `--trust` presses Check on the untrusted import, expects the TrustDialog instead of a run, presses
"Trust and run" and waits for that Check (it counts as the `--check` step). After training, `--export-brain` saves
the active brain through the ShareDialog (`saveTo`, no file dialog) and `--import-brain` adds a `.vrl` with
`ProjectWindow::importBrain(file, false)` (Check, spec, `import_brain`); the new brain must become the active one.
`--panic` ends the train step with `ProjectWindow::panicStopAll()` (what the macOS/Windows hotkey runs) instead of
Stop.
Order: open/import → trust → check → train → export-brain → import-brain → inject-error → screenshot. A project
with a `start_program` gets it started like in the app (the Check and the Train step wait for the 2 s "Starting
the game…" first; the tests use a harmless stand-in, never a real game window). With
`$VYRN_SMOKE_DIALOG_SHOTS=<folder>` it also saves a PNG of each dialog it shows (import, trust, export). App
settings (QSettings, e.g. the remembered author) go to the run's temp folder, never the person's config. The keys:

| Key | When | Meaning |
|---|---|---|
| `ok` | always | every requested step succeeded (exit 0; 1 otherwise, 2 for bad arguments) |
| `tabs` | always | editor tab file names, in order |
| `bottom_tabs` | always | bottom dock tab titles without counts: Console, Points, Problems, Docs |
| `rounds` | always | rounds in the Points chart |
| `error_marker` | always | `{"file","line"}` of the first error mark in points.py, or null |
| `check_ok` | always | the Check passed (null when no Check was asked for) |
| `injected` | `--inject-error` | `{"file":"points.py","line":N}`: where the NameError went |
| `screenshot` | `--screenshot` | the PNG's absolute path |
| `failures` | when any | plain-text reasons, one per failed step |
| `imported` | `--open-package` | the import worked (false only in the early-exit line `{"ok":false,"imported":false,"failures":[…]}`) |

## 10. Linux, macOS and Windows (`AppPlatform.h`)

The app follows docs/dev/platforms.md. Core matters come from `vyrn/platform.h` (`ensure_passive_openmp`,
`stop_process_tree`, `release_all_keys`, `runtime_dir`, `default_python`, `executable_path`, `write_file_atomic`).
What only the app does differently is behind `app/AppPlatform.h` (namespace `app_platform`), implemented once per
system in `app/platform_linux.cpp`, `app/platform_mac.cpp` and `app/platform_win.cpp`; app/CMakeLists.txt builds
exactly one of them (the glob skips `platform_*.cpp`). No other file in app/ uses `#ifdef` for the system: they ask
`app_platform::os()` (a runtime value) or call the functions.

| | Linux | macOS | Windows |
|---|---|---|---|
| Panic shortcut text (banner, countdown, Setup) | Ctrl+Alt+Esc | Control+Option+Esc | Ctrl+Alt+Esc |
| Panic key | labwc keybinds → `vyrn-panic` | Carbon `RegisterEventHotKey` (also with Shift) | `RegisterHotKey` `MOD_CONTROL\|MOD_ALT` (+ `MOD_SHIFT`) `VK_ESCAPE` on a message-only window: a `QAbstractNativeEventFilter` takes `WM_HOTKEY` from Qt's loop, the window procedure during Windows' own modal loops |
| Start program's process group | `setpgid(0, 0)` in the child | same | none (the tree is found by parent ids) |
| `isOwnChild(pid)` | `/proc/<pid>/stat` ppid | `proc_pidinfo(PROC_PIDTBSDINFO)` ppid | Toolhelp snapshot parent + started after this process |
| Permissions | none | `AXIsProcessTrusted`, `CGPreflightScreenCaptureAccess`, `CGRequestScreenCaptureAccess` | none |
| Pick area | slurp + grim (Wayland) | overlay, points | overlay, physical pixels |
| vyrn-cli for agents (AgentsDialog) | `~/.local/bin/vyrn-cli` | `~/Applications/Vyrn.app/Contents/MacOS/vyrn-cli` | `%LOCALAPPDATA%\Programs\Vyrn\bin\vyrn-cli.exe` |

- **Panic hotkey** (macOS, Windows; `ProjectWindow::panicStopAll()`, run from the event loop): every project window
  that runs or waits for its game stops at once like Stop (a game Vyrn started keeps running, as with `vyrn-panic`),
  says "Panic stop" (console line + toast); then the Python workers of this app are killed with what they started:
  each `<runtime_dir>/<pid>.pid` whose process is a child of this app (`app_platform::isOwnChild`) gets
  `stop_process_tree(pid, true)`, after the panic marker `<runtime_dir>/panic` is written (so the core reports a
  panic stop); then `vyrn::platform::release_all_keys()`, and once more 300 ms later. Workers of vyrn-cli or the MCP
  server are not this app's: on macOS and Windows the hotkey stops the app's runs only.
- **AgentsDialog**: the lines run vyrn-cli found next to this program (every installer puts it there), else where
  this system's installer puts it (`paths::installedCli()`); shown with `~` on Linux and macOS, in double quotes when
  needed on Windows (PowerShell and Command Prompt).
- **Build** (app/CMakeLists.txt): `vyrn_executable(vyrn)` (Windows: the UTF-8 manifest); `WIN32_EXECUTABLE`,
  `MACOSX_BUNDLE`. macOS: `OUTPUT_NAME Vyrn` (so `Vyrn.app/Contents/MacOS/Vyrn`), bundle id `org.vyrn.vyrn` (ends in
  `.vyrn`, which the focus guard recognizes), version from the project, an `.icns` made at configure time from
  `packaging/vyrn.png` (or a 1024 px drawing by `packaging/make_icon.py` when Pillow is there) with `sips` +
  `iconutil` (none: no icon), links `ApplicationServices` and `Carbon`; `cmake --install` copies `python/`,
  `templates/`, `docs/user/` (as `docs`) and `tools/link` into `Vyrn.app/Contents/Resources/vyrn` (the top-level
  `vyrn_install_data()`), where `find_data_dir()` looks (a build folder's bundle finds the source tree instead);
  vyrn-cli goes into `Contents/MacOS` (the top-level CMakeLists.txt points `CMAKE_INSTALL_BINDIR` there). Windows: `vyrn.rc` with
  `packaging/vyrn.ico`, else an `.ico` Pillow makes from `packaging/vyrn.png` at configure time (none: no icon);
  links `user32`.
- Linux keeps its behaviour: slurp/grim, the labwc panic keys, `/usr/bin/python3`, `~/.local/bin`.
